# Vectorized operation improvement plan

Audited 2026-10-04 against the current working tree, including existing uncommitted runner/entrypoint changes. Scope: `src/application/xauusd_trading_strategy_1_vector/__main__.py` → `run_vectorized_strategy` → `process_tick_data` → `process_native_stream`, their active market/execution collaborators, manifest persistence, result projection and reporting. Recorded-native replay is a separate related entrypoint. This is an audit and implementation plan; F1 is **IMPLEMENTED** as described in its row, and every remaining runtime replacement below is **NOT IMPLEMENTED**.

## Required policy

- **DONE:** Skills require pandas DataFrames first, NumPy ndarrays second, and prohibit Python per-tick/per-candle iteration, including previous/closed-candle history scans. Stateful dependencies do not authorize a Python loop.
- **DONE:** The exact fourteen-level operation priority is recorded in [project-decisions](../../.codex/skills/project-decisions/SKILL.md#vectorized-pandasnumpy), linked from optimization-review and the `.agents` decision skill. Numba is a compiled ndarray fallback only when pandas/NumPy cannot efficiently express the calculation. Python iteration is last resort only over non-market-row orchestration units.
- `itertuples`, `iterrows`, comprehensions, generators, row-wise `apply`, Python callbacks in `map`, `np.vectorize`, and helper-hidden loops remain violations when they process ticks/candles. A DataFrame wrapper around scalar transitions does not satisfy this policy.
- Loops over daily files, instruments or fixed schema fields are distinct from market-row iteration; their calculations must remain batched. Preserve causal inputs, callback ordering, all state fields and strict output schemas.

## Acceptance invariants

- No Python tick/candle iteration remains in reachable processing, historical features, persistence/projection, export/summary or the recorded adapter; no `apply`/`map`/`np.vectorize` escape. Non-market orchestration calls batch calculations.
- Preserve MarketState phase order: begin-tick/session → on new bar, age and previous-close breakouts → day change → bar/open/engagement initialization → restart gate → settle → trend update → touches/reversals → pullbacks → management → previous-bid update → snapshots/trace. A day-boundary rewrite must preserve breakout-before-day-reset behavior.
- Causal native candle features exclude the current candle; retain three-closed-candle startup, unique native M15 coverage, missing-bar behavior and the exact structure-stop scan bounds. Avoid synthetic bars and look-ahead in extremum confirmation.
- Preserve all state variables, IDs, zone priority/ties, callback failure effects, pending risk, execution economics, duplicate-tick row order, stream isolation and terminal state across day partitions. Separate signal-only and execution assertions.
- State and result indexes match original market rows; precise timestamps stay UTC nanoseconds; Pandera schema validation rejects broken inputs and output contracts remain exact. Grouped joins cannot duplicate/drop ticks.
- Runtime equivalence tests use current behavior as characterization where it matches confirmed rules; native parity requires matched native evidence and first-difference checks. Measure performance/memory before making speed claims. This documentation change does not establish runtime compliance or parity.
